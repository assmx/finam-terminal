# Spec: Analytics — валюты: оценка иностранных активов и структура портфеля по валюте

## Problem

Вкладка Analytics считает всё в базовой валюте счёта (RUB), и для всего, что номинировано в других валютах, картина сейчас неверна:

- Стоимость позиции = цена × количество (`analytics.PositionValue`), валюта инструмента не учитывается. Бумага в юанях или долларах складывается с рублёвыми как рубли — в «Структуре», «Концентрации», плече и в колонке Value вкладки Positions.
- `analytics.StructureInput.Currencies` предусмотрен, но в рабочем коде не заполняется, поэтому строка «в других валютах: N» не появляется никогда.
- Остатки денег в других валютах (`GetAccountResponse.cash`) в доли не входят: сейчас они только перечислены строками `остаток <валюта>` в «Маржа и риск».
- Разреза структуры по валюте нет вовсе. В терминале брокера он есть (Инструмент / Тип / Валюта / Сектор / Страна), и пользователь сверяется с ним.
- В Trade API нет метода курсов валют. Прежние треки из-за этого исключили конвертацию (`analytics_overview_20260903`, `analytics_history_20260903`, «Out of Scope»).

Жёсткое ограничение заказчика, как у всех треков вкладки: **стабильная работа без риска упереться в лимиты Finam API**. Источник данных — только Trade API, без внешних сервисов и локального хранилища.

## Solution

### Контекст и границы трека

Трек меняет **текущую оценку**: «Обзор» (структура, секторы, концентрация, плечо, «Оценка», «Маржа и риск») и колонку Value вкладки Positions. История («Сделки», «Деньги», «Итог с открытия», «Выплаты») остаётся по валютам без пересчёта: применять сегодняшний курс к прошлым потокам неверно.

### Решения, принятые с пользователем (2026-09-10)

| Вопрос | Решение |
|---|---|
| Где показать разрез по валюте | **Отдельная панель «Валюты»** в левой колонке «Обзора» под «Структурой портфеля». Всё видно сразу, без переключений; при нехватке высоты по-прежнему первым ужимается «Итог с открытия». |
| Куда относить иностранные деньги в разрезе по типу | **В группу «Валюта»**, как у брокера. Рубли остаются строкой «Кэш». |
| Валюта риска у замещающих облигаций и бумаг, где валюта котировки не совпадает с валютой торгов | **Валюта номинала** (`bond_details.currency`): стоимость и купоны привязаны к номиналу, рубли — лишь способ оплаты. Для не-облигаций — валюта котировки (`quote_currency`). |
| Данные для разведки | **Токен с торговым счётом, на котором есть иностранные активы** — разведка отвечает на вопросы о единицах цен и P&L на живых данных, а не переносит их в смоук. |

### Бюджет API

| Данные | Источник | Цена |
|---|---|---|
| Валюта инструмента, номинал облигации | ответ `GetAsset`, который **уже** делается один раз за сессию на инструмент ради лота (`resolveAssetLot`, `fetchAssetLotSize`) и в профиле (`GetAssetInfo`); сейчас `quote_currency` и `bond_details` из него выбрасываются | **0** |
| Остатки по валютам | `GetAccount.cash`, тот же пятисекундный ответ | 0 |
| Курсы | котировка пары к рублю по символу из таблицы `fxSymbols` — редким `LastQuote` или через поток котировок (выбор по итогам разведки, см. ниже) | не больше 1 на иностранную валюту, реально присутствующую на счёте, за `fxRateTTL`; только пока «Обзор» на экране; для счёта только в рублях — 0 |
| Перерисовка «Обзора» | память | **0** (существующий тест на 20 перерисовок расширяется счётчиками `GetAsset` и котировок курсов) |

### Валюта инструмента (API-слой)

```go
// models
type InstrumentCurrency struct {
    Quote     string  // GetAsset.quote_currency как прислал брокер; "" = не сообщил
    Face      string  // bond_details.currency; "" у не-облигаций
    FaceValue float64 // bond_details.bond_face_value; 0 = не сообщён
}

// api — чистое чтение кеша, запроса не делает никогда (как GetInstrumentType)
func (c *Client) GetInstrumentCurrency(symbol string) (models.InstrumentCurrency, bool)
```

- Заполняется во **всех трёх** местах, где уже вызывается `GetAsset`: `resolveAssetLot`, `fetchAssetLotSize`, `GetAssetInfo`. Ключи — тикер и полный символ, как у кеша лотов; под тем же `assetMutex`.
- Успешный ответ кешируется **всегда**, даже с пустыми полями: «брокер проверен, валюты не сообщил» и «ещё не спрашивали» — разные состояния, второй флаг `bool` их различает. Неудачный вызов не кешируется (повтор при следующем промахе лота — существующее поведение).
- Новых вызовов `GetAsset` трек не добавляет: интеграционный тест сверяет счётчик мока до и после.

### Курсы

```go
// models
type FXRate struct {
    Currency string
    Rate     float64   // единиц базовой валюты за 1 единицу Currency
    At       time.Time // время котировки
}
```

- `fxSymbols` — переменная пакета `api`: валюта → символ пары и множитель котировки (некоторые пары котируются за 10 или 100 единиц). Заполняется по итогам разведки; валюта вне таблицы — «нет курса».
- Цена курса: `last`, при его отсутствии `close`; время — `timestamp` котировки. Нечитаемое, нулевое или отрицательное значение — «нет курса».
- **Способ получения выбирается в фазе 1** по фактам:
  - *редкий `LastQuote`* (по умолчанию): `Client.GetFXRates(currencies)` — один вызов на валюту, свой дедлайн на вызов, `ResourceExhausted` обрывает пачку (как `GetQuotes`); UI держит независимый от счёта кеш `fxRates`, обновляет его при видимом «Обзоре», если на активном счёте есть иностранная валюта и курс старше `fxRateTTL`; флаг in-flight; результаты после `Stop()` отбрасываются;
  - *поток котировок*: символы пар присоединяются к подписке, пока открыта вкладка Analytics, **после позиций и перед индексом** (как состав индекса на вкладке Index); котировки складываются в независимую от счёта карту. Выбирается, если `LastQuote` вне сессии пуст или курс нужен чаще, чем раз в `fxRateTTL`.
- `ResourceExhausted` — защёлка на сессию, строка состояния «лимит API: курсы не обновляются, R — вручную», `R` работает. Обычная ошибка по одной валюте — «нет курса» у неё, остальные не страдают, защёлки нет; следующая попытка — по расписанию, не сразу.
- Базовая валюта не RUB (счёт только в долларах) — пересчёт через рубль: курс X/базовая = X/RUB ÷ базовая/RUB, если известны оба; иначе «нет курса».

### Правила расчёта

**Валюта позиции.** Облигация с непустым `Face` → `Face`; иначе `Quote`; если оба пусты или кеш ещё пуст — валюта **неизвестна**: позиция считается в базовой валюте, как сейчас (гадать значило бы молча уменьшать портфель), и учитывается счётчиком «валюта неизвестна: N».

**Стоимость позиции.** `value_native` = количество × цена (для облигаций, котирующихся в процентах от номинала, — × номинал / 100, если разведка это подтвердит; тогда же номинал включается и в `PositionValue` вкладки Positions); `value_base` = `value_native` × курс валюты позиции. Функция по-прежнему одна на оба экрана — они не могут разойтись.

**База долей.** Σ |`value_base`| позиций + кэш в базовой валюте + положительные иностранные остатки **с курсом**, пересчитанные. Заём (отрицательный остаток) в базу не входит и остаётся строкой «заём» в «Маржа и риск». Позиции и остатки **без курса** в базу не входят, показываются в своей валюте и считаются счётчиком.

**Разрез по типу.** Считается на пересчитанной базе. Иностранные остатки с курсом входят в группу «Валюта» (решение), рублёвые — в «Кэш». «в других валютах: N» остаётся только для позиций без курса.

**Разрез по валюте.** Одна строка на валюту: сумма позиций этой валюты по модулю плюс её положительный остаток, в базовой валюте; доля от той же базы, что у структуры, поэтому доли в сумме дают 100%. Порядок детерминированный: базовая валюта первой, дальше по убыванию суммы, при равенстве — по коду. Валюты без курса — в конце, без доли и полосы, суммой в своей валюте с пометкой «нет курса».

**Секторы, концентрация, плечо** — на пересчитанных стоимостях.

**«Оценка».** Если разведка покажет, что `daily_pnl`, `unrealized_pnl` и `average_price` позиции приходят в валюте инструмента, `analytics.Valuation` пересчитывает их по позиции; позиция без курса учитывается как неотчитанная (как FORTS-позиция без `daily_pnl`), со своей строкой-пометкой. Если они приходят в рублях — «Оценка» не меняется.

**Инварианты пакета `analytics`** сохраняются: чистые функции без I/O и tview, никаких NaN/Inf, невычислимое — через `Valid` → «Н/Д». Новый инвариант, закреплённый property-тестом на случайных входах: **ни одна сумма не складывает разные валюты без курса**, и доли разреза по валюте и разреза по типу дают одну и ту же базу.

### UI

- **Панель «Валюты»** в левой колонке «Обзора» между «Структурой портфеля» и «Секторами», высота по содержимому с потолком `maxCurrencyLines`. Строки — тем же `shareRow`, что и структура (код, сумма в базовой валюте, доля, полоса). Под строками серым по одной строке на иностранную валюту: сумма в своей валюте, курс и его время (`CNY 12 400.00 × 11.4100 · 14:05`); устаревший курс помечен (`курс на 06.09 23:49`), а не выдаётся за текущий. Валюта без курса — жёлтой строкой `USD 1 250.00 — нет курса`.
- **«Маржа и риск»**: строки `остаток <валюта>` уходят в панель «Валюты» (одно число — одна рамка, тот же принцип, что при переносе эквити в «Оценку»); строки `заём <валюта>` остаются — это риск.
- **Positions**: у позиции в небазовой валюте денежные ячейки несут код валюты, единицы в колонке не смешиваются молча. Какие именно ячейки — по итогам разведки (цены — в валюте котировки; P&L — в той валюте, в которой его присылает брокер).
- **Состояние «Обзора»**: строка статуса сообщает загрузку курсов, их отказ по лимиту и защёлку; «Обзор» без курсов остаётся рабочим — всё иностранное показывается в своей валюте.
- `R` на «Обзоре» дополнительно обновляет курсы (с уважением к защёлке и `fxRateTTL`).

### Ошибки и устойчивость

- `GetAsset` по символу не ответил → валюта неизвестна → базовая валюта со счётчиком; повтор — существующим путём при следующем промахе лота.
- Курс по валюте не получен → «нет курса» у неё; `ResourceExhausted` → защёлка на сессию; автоповторов после ошибки нет, обновление только по расписанию `fxRateTTL` и по `R`.
- Переключение счёта: кеш курсов общий для всех счетов, новая валюта запрашивается только если её курса нет или он старше `fxRateTTL`.
- `Stop()` приложения: результаты загрузки курсов после остановки в UI не пишутся.

### Разведка на реальном API (фаза 1 трека)

Одноразовая программа с токеном пользователя, у которого есть торговый счёт с иностранными активами; в репозиторий не попадает. Результаты фиксируются разделом «Результаты разведки» в этом файле и в CLAUDE.md, символы и константы (`fxSymbols`, `fxRateTTL`, порог устаревания курса, `maxCurrencyLines`) назначаются по фактам.

1. Что возвращают `GetAsset.quote_currency` и `bond_details.{currency, bond_face_value}` для рублёвой акции, облигации в юанях, замещающей облигации (номинал USD, расчёты в RUB), фонда и валютного инструмента. Бывает ли `quote_currency` пустым.
2. В каких единицах приходят `current_price`, `average_price`, `daily_pnl`, `unrealized_pnl` позиции для иностранной бумаги и для облигации (% от номинала или деньги; валюта инструмента или RUB), и в какой валюте `equity` и `unrealized_profit` счёта. Закрывает вопрос о формате цены облигации, открытый с трека `analytics_overview_20260903`.
3. Как отражается купленная валюта: строкой в `cash` (CNY) или позицией (`CNYRUB_TOM@MISX`)?
4. Символы курсов: какие инструменты дают CNY/RUB, USD/RUB, EUR/RUB и прочие валюты счёта через `LastQuote` (кандидаты — пары `…_TOM@MISX` и валютные символы с MIC `#WWCP` из переписи `Asset.Type = CURRENCIES`); множитель котировки; отвечают ли они вне торговой сессии и в выходные (`last` против `close`, `timestamp`); нет ли отказа по правам. Отдельно проверить гипотезу, что биржевые торги USD и EUR на MOEX остановлены и котировок по ним нет, — тогда нужен другой источник внутри Trade API или честное «нет курса».
5. Сверка: сумма пересчитанных позиций и остатков против `equity` брокера — насколько сходится.
6. По итогам — выбор между `LastQuote` и потоком для курсов и значение `fxRateTTL`.

## Requirements

### Функциональные
- Каждая позиция и каждый денежный остаток оцениваются в своей валюте и пересчитываются в базовую, когда курс есть.
- Панель «Валюты» на «Обзоре»; структура по типу, секторы, концентрация и плечо — на пересчитанной базе; иностранные деньги — в группе «Валюта».
- Облигации оцениваются через номинал, если разведка подтвердит котировку в процентах.
- Валюта без курса показывается в своих единицах с пометкой и в доли не входит; неизвестная валюта считается базовой со счётчиком.
- Колонка Value вкладки Positions и панели Analytics не смешивают валюты молча.

### Технические
- `models`: `InstrumentCurrency`, `FXRate`.
- `api`: кеш валюты инструмента из существующих ответов `GetAsset`, `GetInstrumentCurrency`, `fxSymbols`, получение курсов выбранным способом; testserver: фикстуры облигации в юанях, облигации с номиналом в USD, валютной строки в `cash`, котировки курсов, счётчики.
- `analytics`: валюта позиции, пересчёт, база, разрез по валюте, изменения `Structure`/`Valuation`/`RiskMetrics`; табличные тесты и property-тест инварианта.
- `ui`: панель «Валюты», перенос строк `остаток`, кеш курсов и его жизненный цикл, валюта в колонках Positions, строка состояния, `R`.
- Пакет `analytics` не импортирует `api` и `ui`; ничего нового в `go.mod`.
- TDD, покрытие нового кода ≥ 80%, race-детектор (гейт CI), golangci-lint чист.

## Acceptance Criteria
- [ ] Разведка зафиксировала поля валюты `GetAsset`, единицы цен и P&L позиций, отражение купленной валюты, символы и поведение котировок курсов, сверку с `equity`; выбран способ получения курсов, константы выставлены.
- [ ] Разрез «Валюты» на «Обзоре»: доли по пересчитанной базе дают 100%; порядок детерминирован (базовая первой, дальше по сумме); валюты без курса — в конце, без доли, с суммой в своей валюте.
- [ ] Курс и его время видны; устаревший курс помечен.
- [ ] Property-тест: ни одна сумма не складывает разные валюты без курса; разрезы по типу и по валюте дают одну базу.
- [ ] Счётчики мока: `GetAsset` по позициям — столько же вызовов, сколько до трека; котировки курсов — не больше одной на валюту за `fxRateTTL`; для счёта только в рублях — ноль; 20 перерисовок «Обзора» — ноль запросов любого вида.
- [ ] `ResourceExhausted` на курсах защёлкивает их до конца сессии с сообщением; `R` работает; обычная ошибка по одной валюте не трогает остальные.
- [ ] Колонка Value вкладки Positions несёт код валюты у небазовой позиции.
- [ ] Интеграционные тесты через bufconn: маппинг валюты из `GetAsset` и путь курса.
- [ ] `go test ./...`, `go test -tags=integration ./api/...`, `-race` обеих сюит (CI) и `golangci-lint` — зелёные; покрытие нового кода ≥ 80%.
- [ ] Ручной смоук на реальном счёте: панель «Валюты» сходится с разрезом «Валюта» терминала брокера; ни одного `ResourceExhausted`.
- [ ] Документация: `docs/user_manual/analytics.md`, `docs/user_manual/positions.md`, CLAUDE.md, CHANGELOG.md.

## Edge Cases
- Счёт только в рублях → панель «Валюты» с одной строкой базовой валюты, ни одного запроса курсов.
- Иностранные деньги без иностранных бумаг → курс нужен, строка валюты состоит из остатка.
- Отрицательный иностранный остаток → «заём» в «Маржа и риск», в разрез по валюте не входит.
- Курс нечитаемый, нулевой или отрицательный → «нет курса».
- `quote_currency` пуст у не-облигации → валюта неизвестна → базовая со счётчиком.
- У облигации пуст `Face`, но есть `Quote` → валюта котировки.
- Шорт в иностранной валюте → по модулю, как в структуре.
- Выходные и праздники → курс по последнему закрытию с пометкой устаревания.
- Пара котируется за 100 единиц → множитель из `fxSymbols`.
- Базовая валюта не RUB → кросс-курс через рубль или «нет курса».
- Курс пришёл посреди сессии → доли меняются на следующей перерисовке, без запроса.
- Переключение счёта → общий кеш курсов, новая валюта — только при отсутствии или устаревании курса.
- `Stop()` во время загрузки курсов → ничего не пишется в UI.

## Out of Scope
- Пересчёт исторических потоков («Сделки», «Деньги», «Итог с открытия», «Выплаты») по курсу.
- Разрез по странам.
- Внешние источники курсов (ЦБ и т. п.) и хранение курсов между сессиями.
- Пересчёт вариационной маржи FORTS.
