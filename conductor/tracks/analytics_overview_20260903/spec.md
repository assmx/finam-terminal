# Spec: Вкладка Analytics — обзор портфеля, маржа и риск, квоты API

## Problem

Терминал показывает позиции, историю сделок и заявки, но не отвечает на вопросы, ради которых инвестор открывает счёт: из чего состоит портфель и насколько он сконцентрирован, сколько маржи задействовано и далеко ли до маржин-колла, сколько запросов к Trade API ещё осталось в текущем окне. Всё это уже есть в данных, которые терминал получает каждые 5 секунд, либо стоит один запрос, но ни одно из этих чисел не показывается.

Жёсткое ограничение заказчика (как и у вкладки Index): **стабильная работа без риска упереться в лимиты Finam API**. Источник данных только Trade API, без внешних сервисов и локального хранилища.

## Solution

### Контекст: вкладка Analytics целиком

Пятая вкладка `Analytics` (Positions | History | Orders | Index | Analytics) с под-экранами внутри, переключаемыми цифрами. В целевом виде (после двух треков):

```
 [1] Обзор  [2] Сделки  [3] Деньги  [4] Выплаты  [5] API        Период: 3М   R обновить
```

| Под-экран | Что показывает | Трек |
|---|---|---|
| Обзор | структура портфеля (типы, секторы, кэш, концентрация), маржа и риск; позже итог с открытия счёта и IMOEX | 1 (+2) |
| Сделки | реализованный P&L по FIFO и статистика закрытых сделок за период | 2 |
| Деньги | комиссии, налоги, выплаты, вводы/выводы за период; итог с открытия, XIRR, сравнение с IMOEX | 2 |
| Выплаты | ожидаемые дивиденды, купоны, амортизации, оферты по позициям | 2 |
| API | квоты Trade API: лимит, остаток, время сброса по методам | 1 |

Разбиение на два трека сделано по цене в запросах: этот трек добавляет только блоки, которые считаются из уже загруженных данных, плюс один запрос квот. Второй трек («история, деньги, выплаты, бенчмарк») опирается на `AccountsService.Trades`/`Transactions`, календари и бары и требует разведки лимитов на реальном ключе.

**В этом треке шапка вкладки показывает `[1] Обзор  [2] API`**; трек 2 вставляет остальные экраны, и нумерация становится финальной. Каркас (перечисление под-экранов, кеши по счёту, состояние вкладки) сразу проектируется под пять экранов.

### Что делает этот трек

1. **Обзор**: две колонки. Слева структура портфеля по типам инструментов (Акции, Облигации, Фонды, Фьючерсы, Опционы, Валюта, Прочее, строка Кэш) с долями и полосами, ниже строка секторов (для бумаг из состава IMOEX). Справа блок «Маржа и риск» (собственные средства, доступный кэш, начальная и минимальная маржа, использование маржи, запас до маржин-колла, плечо), ниже «Концентрация» (топ-3 позиций по доле, число позиций).
2. **API**: таблица квот `UsageMetricsService.GetUsageMetrics` с сортировкой по доле остатка, цветами и полосой использования; строка времени последнего запроса.

### Бюджет API (ключевое проектное решение)

| Данные | Источник | Цена |
|---|---|---|
| Позиции, эквити, котировки | уже в памяти: тик 5 с (`GetAccount`) и стрим `SubscribeQuote` | 0 |
| Кэш, маржа, дата первой сделки | новые поля того же ответа `GetAccount`, сейчас выбрасываются | 0 |
| Тип инструмента | `Asset.Type` из bulk-списка `Assets`, который уже загружается при старте, сейчас выбрасывается | 0 |
| Сектор | состав IMOEX (`GetIndexConstituents`, кеш 24 ч, общий с вкладкой Index) | 1–2 в сутки, общие с Index |
| Квоты | `GetUsageMetrics` при входе на под-экран «API» и по `R` | 1 |

«Обзор» перерисовывается на каждом тике из памяти, сетевых вызовов в рендере нет. Квоты не обновляются автоматически. Ни один загрузчик не повторяет запрос сам после ошибки.

### Архитектура

- **`analytics/` (новый чистый пакет)**: только функции над `models` и простыми типами, без I/O и без tview. Строковые числовые поля существующих моделей разбираются одним помощником; нечитаемая запись исключается и увеличивает счётчик `Skipped`. Функции не паникуют на пустых срезах и не возвращают NaN/Inf: неопределённые значения помечаются флагами `Valid`. Пакет не импортирует `api` и `ui`.
- **`api/`**: маппинг новых полей `GetAccount`, тип инструмента в кеше активов, `GetUsageMetrics` и седьмой клиент сервиса в `newClientFromConn`.
- **`ui/analytics.go`** (состояние вкладки, загрузки, клавиши) и **`ui/analytics_render.go`** (компоненты и отрисовка); `TabAnalytics` в `tabLabels`; подсказки статус-бара.
- `APIClient` (интерфейс в `ui/app.go`) растёт на `GetUsageMetrics` и `GetInstrumentType`; мок-клиент тестов соответственно.

Отклонены: расчёты внутри `ui/` (логика не тестируется без tview, `ui/` уходит за 7 000 строк) и внутри `api.Client` (бизнес-логика в транспортном слое, тесты только через `bufconn`).

### Модели

```go
// models
type CashBalance struct {
    Currency string
    Amount   float64
}

// Дополнение AccountInfo (существующие строковые поля не трогаем)
PortfolioKind     string        // "MC", "MCT", "FORTS"; "" если oneof пуст
Cash              []CashBalance // GetAccountResponse.cash: собственные средства по валютам, без маржинальных
AvailableCash     float64       // MC.available_cash или FORTS.available_cash
InitialMargin     float64       // MC.initial_margin
MaintenanceMargin float64       // MC.maintenance_margin
MoneyReserved     float64       // FORTS.money_reserved
HasMarginData     bool          // true, если портфель MC или FORTS отдал поля выше
FirstTradeDate    time.Time     // нулевое время, если API не прислал
FirstNonTradeDate time.Time

// SecurityInfo получает поле Type string (Asset.Type как есть)

type QuotaUsage struct {
    Name      string
    Limit     int64
    Remaining int64
    ResetAt   time.Time
}
```

Новые методы клиента: `GetInstrumentType(symbol string) string` (поиск по полному символу и по тикеру, пустая строка при отсутствии) и `GetUsageMetrics() ([]models.QuotaUsage, error)`.

### Правила расчёта: структура портфеля

- База долей = сумма стоимостей позиций в базовой валюте счёта + денежные остатки в базовой валюте. Эквити брокера для долей не используется (содержит маржинальные средства). Доли всегда суммируются в 100%.
- Базовая валюта: `RUB`, если есть среди записей `cash`; иначе валюта первой записи; при пустом списке `RUB`.
- Стоимость позиции — та же, что в колонке Value вкладки Positions: `|количество в штуках| × last` из живой котировки, а при её отсутствии × `CurrentPrice` брокера. Формула выносится в общий помощник, чтобы Positions и Обзор не расходились. Для облигаций при цене в процентах от номинала стоимость = цена / 100 × номинал × количество; включается только по результату разведки (см. ниже), одной правкой для обоих экранов.
- Тип инструмента: `Asset.Type` → группа по таблице соответствия (одна переменная в `analytics`, регистр не важен, неизвестные значения → Прочее). Ожидаемые значения `EQUITIES` → Акции, `BONDS` → Облигации, `FUNDS` → Фонды, `FUTURES` → Фьючерсы, `OPTIONS` → Опционы, `CURRENCIES` → Валюта; фактические значения фиксирует разведка.
- Секторы: только для бумаг из состава IMOEX, остальное «Прочее». При недоступном составе строка «секторы: состав индекса недоступен».
- Концентрация: топ-3 позиций по доле и общее число позиций.
- Позиции в валюте, отличной от базовой, в доли не входят и показываются строкой «в других валютах: N позиций». Валюта позиции без `GetAsset` неизвестна, поэтому в этом треке иновалютными считаются только позиции, у которых валюта котировки известна из кеша и отличается от базовой; разрез «по валютам инструментов» не делается, денежные остатки по валютам видны в блоке маржи.
- Курсов в API нет, конвертации нет.

### Правила расчёта: маржа и риск

Портфель MC: собственные средства (`cash` по валютам, отрицательное значение означает заём), доступный кэш, начальная и минимальная маржа, и три вычисленных числа:

- использование маржи = начальная маржа / эквити;
- запас до маржин-колла = (эквити − минимальная маржа) / эквити;
- плечо = сумма |стоимостей позиций| / эквити.

Цвет: использование ниже 50% зелёный, от 50 до 80% жёлтый, выше 80% красный; запас зеркально (выше 50% зелёный, от 20 до 50% жёлтый, ниже 20% красный). Плечо без цвета.

Портфель FORTS: вместо маржи `money_reserved`; использование ГО = резерв / эквити с теми же порогами; плечо «Н/Д». Портфель MCT и пустой oneof: «Н/Д» по всем вычисляемым строкам. Нулевое эквити → «Н/Д».

### Правила: квоты

Все квоты из ответа, сортировка по доле остатка (`Remaining / Limit`) по возрастанию: метод (имя как прислал API), лимит, остаток, сброс через мм:сс, полоса использования. Остаток ниже 20% красный, ниже 50% жёлтый, иначе зелёный. `Limit` = 0 → доля не считается, строка идёт в конец без цвета. Внизу время последнего запроса.

### UI и навигация

- Пятая вкладка `Analytics` в `tabLabels`; ←/→ подхватывают её без правок (цикл по длине списка).
- Внутри: шапка в одну строку (под-экраны, в этом треке `[1] Обзор  [2] API`) над `tview.Pages`. Обзор — `Flex` из двух колонок `TextView`; API — таблица с закреплённой шапкой (`SetFixed(1, 0)`) и расширением колонок на каждой ячейке, как у Index, плюс строка времени внизу.
- Клавиши на вкладке: `1`/`2` под-экран; `R`/`К` обновить текущий под-экран (Обзор — только состав индекса, если он ещё не загружен; API — квоты). Клавиши `P` (период), `Enter` и `A` появятся в треке 2.
- Статус-бар на вкладке: `1-2 Экран  R Обновить`.
- Под-экран с таблицей отдаёт фокус таблице (↑/↓), Обзор держит фокус на контейнере; `activeTabTable()` для вкладки возвращает то, что под-экран считает фокусируемым.
- Состояние вкладки (под-экран) одно на сессию; кеши по счёту хранятся в карте по идентификатору счёта (в этом треке карта используется только для квот, общих для всех счетов, но структура сразу под трек 2).
- «Обзор» перерисовывается на тике в той же точке, где сейчас `updateIndexTable`, и при применении данных счёта, когда вкладка активна. На первом показе вкладки вызывается существующий `ensureIndexLoaded()` ради секторов; индексные символы в подписку он не добавляет (набор стрима зависит от активной вкладки Index, не Analytics).
- Индикация: у каждого под-экрана своя строка состояния под шапкой — жёлтым загрузка, красным ошибка с подсказкой «R повторить», серым «Н/Д» в строках, которые для этого типа счёта не считаются.
- Подписи под-экранов и заголовки блоков на русском (как «Индекс МосБиржи» на вкладке Index); имя вкладки английское, как у остальных.
- Ширина: макет рассчитан на 80 колонок области вкладки; при меньшей ширине колонки `Flex` сжимаются пропорционально, имена усекаются существующим `truncate`.

### Ошибки и устойчивость

- Ошибка `GetUsageMetrics` → строка ошибки на под-экране «API» с подсказкой `R`, никакого автоповтора. `ResourceExhausted` показывается тем же сообщением с пометкой «лимит API».
- Недоступный состав индекса не ломает Обзор: строка «секторы: состав индекса недоступен», остальные блоки живут.
- Счёт с `LoadError` → Обзор показывает существующее сообщение о недоступности счёта.
- Нечитаемые числа в строковых полях исключаются со счётчиком; деления защищены; NaN/Inf на экран не попадают.
- Логи: `[INFO]` о загрузке квот (число квот), gRPC-ошибки через `logGRPCError`; суммы в лог не пишутся.

### Разведка на реальном ключе (фаза 1 трека)

Одноразовая программа с реальным токеном, в репозиторий не попадает; результаты фиксируются в этом файле:

1. Фактические значения `Asset.Type` в bulk-списке (для таблицы соответствия типов).
2. Какие поля приходят в `GetAccount` по каждому счёту пользователя: вид портфеля (`portfolio_mc` / `portfolio_forts`), заполнены ли `cash`, `available_cash`, `initial_margin`, `maintenance_margin`, `first_trade_date`.
3. Как приходит `current_price` облигационной позиции: в процентах от номинала или в деньгах (нужна хотя бы одна облигация в позициях; если нет — пункт откладывается до трека 2).
4. Что возвращает `GetUsageMetrics`: имена квот, лимиты, окно сброса.

## Requirements

### Функциональные
- Вкладка `Analytics` пятая в цикле ←/→; шапка `[1] Обзор  [2] API`; переключение под-экранов клавишами `1`/`2`.
- Обзор: структура по типам с долями и полосами, строка секторов, строка Кэш, блок маржи и риска с тремя вычисленными числами и цветами, концентрация (топ-3, число позиций). Данные активного счёта; смена счёта перерисовывает Обзор.
- API: таблица квот с сортировкой, цветами, полосой и временем сброса; загрузка при первом входе и по `R`; время последнего запроса внизу.
- Статус-бар показывает подсказки вкладки.

### Технические
- `models`: `CashBalance`, новые поля `AccountInfo`, `SecurityInfo.Type`, `QuotaUsage`.
- `api`: маппинг oneof `portfolio`, списка `cash` и дат в `GetAccountDetails`; `Type` в `loadAssetCache` и `GetInstrumentType`; `GetUsageMetrics` с `usageMetricsClient`; `MockUsageMetricsServer` в testserver (седьмой сервис) с фикстурой квот и инъекцией ошибок; фикстуры счёта с `cash` и `portfolio_mc`.
- `analytics`: `Structure`, `RiskMetrics`, `SortQuotas`/`QuotaLevel`, помощник разбора чисел, таблица соответствия типов; табличные тесты.
- `ui`: `TabAnalytics`, `AnalyticsView`, состояние вкладки, рендер Обзора из памяти, загрузка квот, клавиши, статус-бар; общий помощник стоимости позиции для Positions и Обзора.
- TDD, покрытие нового кода ≥ 80%, race-детектор (гейт CI), golangci-lint чист.

## Acceptance Criteria
- [ ] Разведка зафиксировала значения `Asset.Type`, состав полей `GetAccount` по счетам пользователя и формат квот.
- [ ] Вкладка `Analytics` пятая в цикле ←/→; шапка показывает `[1] Обзор  [2] API`; `1`/`2` переключают под-экраны; возврат из профиля и модалок приходит на вкладку.
- [ ] Обзор показывает доли по типам (сумма 100%), секторы для бумаг IMOEX, кэш, топ-3 и число позиций, блок маржи с тремя вычисленными числами и цветами; при смене счёта данные меняются.
- [ ] Обзор перерисовывается на тике без единого вызова клиента сверх существующих (счётчик мока по новым методам = 0; `GetIndexConstituents` не чаще одного раза за сессию).

- [ ] Стоимость позиции в Обзоре совпадает с колонкой Value вкладки Positions (общий помощник).
- [ ] `go test ./...`, `go test -tags=integration ./api/...`, `-race` обеих сюит (CI) и `make lint` — зелёные; покрытие нового кода ≥ 80%.
- [ ] Документация: `docs/user_manual/analytics.md`, ссылки из `index.md` и `interface-overview.md`, CLAUDE.md, `conductor/product.md`, CHANGELOG.md, README.md.

## Edge Cases
- Нет позиций и нет кэша → база долей 0 → «Н/Д» вместо долей, блок концентрации пуст, маржа показывается как есть.
- Котировка ещё не пришла → стоимость по `CurrentPrice` брокера; нет и её → позиция исключается из долей со счётчиком «без цены: N».
- Неизвестный `Asset.Type` или бумага вне кеша активов → Прочее.
- Состав индекса грузится или недоступен → строка секторов сообщает об этом, остальное живёт.
- Отрицательные `cash` (заём) → показываются красным как есть, в базу долей не входят (кэш 0 в структуре, строка «заём» в блоке маржи).
- Несколько валют в `cash` → каждая своей строкой в блоке маржи; в базу долей входит только базовая валюта.
- Эквити 0 или не число → все вычисляемые строки «Н/Д».
- Счёт с `LoadError` → Обзор показывает сообщение недоступности, как остальные панели.
- `GetUsageMetrics` вернул пустой список → «квоты не получены» без ошибки.
- `Limit` = 0 у квоты → строка без доли и цвета в конце списка.
- Быстрое переключение `1`/`2` → повторные входы на «API» в течение сессии не делают запросов (только `R`).
- Терминал уже ширины макета → колонки сжимаются, имена усекаются, ничего не переносится на следующую строку.

## Out of Scope
- Под-экраны «Сделки», «Деньги», «Выплаты», период, `Enter`/`A` из таблиц, итог с открытия счёта, XIRR и сравнение с IMOEX — трек 2 («Analytics: история, деньги, выплаты, бенчмарк»).
- Кривая эквити (требует локального хранилища, отклонено заказчиком).
- Конвертация валют и разрез по валютам инструментов.
- Автообновление квот по таймеру.
- `SubscribeAccount` вместо опроса `GetAccount` — отдельный трек.
