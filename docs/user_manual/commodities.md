# Вкладка «Commodities»

Вкладка сопоставляет международную котировку с выбранным фьючерсом MOEX. Данные общие для всех счетов; выбранный счёт используется для запросов брокеру и размещения заявки.

## Котировки и управление

Порядок строк задаёт массив `order` в `~/.finam-cli/commodities.json`. Международные серии: NG/PA/PL на XNYM, Brent на IFEU, GC/SI на XCEC, CC/KC на IFUS, ES на XCME. SI здесь — серебро, не долларовый фьючерс MOEX.

Вкладка устроена как **master–detail**. Верхняя таблица показывает международные серии, нижняя — контракт MOEX выбранной строки. В обеих таблицах одинаковые колонки и ширины: `Ticker`, `Name`, `Price`, `Chg`, `Chg%`, `Volume`; колонки `Updated` нет. Сверху показана международная котировка, снизу — нативная MOEX; изменения и объёмы не пересчитываются. Нижний `Ticker` — биржевое имя из того же каталога, что использует History (например `NG-10.26`), а не код с `@RTSX`. `Name` берётся из одного поля `name`. Профиль показывает это же имя без дополнительных подписей единиц.
Колонка `Ticker` закреплена слева; `Name` получает всю свободную ширину. Числовые колонки `Price`, `Chg`, `Chg%` и `Volume` имеют фиксированную ширину. На узком экране название сокращается раньше числовых значений. Переключение тикеров не сдвигает общую сетку двух таблиц.

После строки MOEX расположен разделитель и три блока «ключ — значение»: **Контракт MOEX** (контракт, экспирация), **Конвертация** (приведённая цена MOEX и дельта `приведённая MOEX − Commodity`), **Обновление** (время котировки Commodity и MOEX). Первые два блока имеют компактную ширину 26 колонок, «Обновление» — 32 для полного времени. Промежуток между блоками — 2 колонки. «Конвертация» начинается под `Name`. На узком экране блоки переносятся вниз. Время выводится в локальном формате `DD.MM.YYYY HH:MM:SS`; отсутствующая дата — прочерк.

- `↑/↓` — выбрать международную строку; нижние котировка, пересчёт, дельта и подсказка заявки меняются сразу, без запроса к API. `Enter` открывает международный профиль с котировкой и свечным графиком.
- В профиле `1–4` выбирают M5/H1/D/W, `R` обновляет данные, `Esc` возвращает в список.
- `R`/`F2` обновляют котировки вне потока и повторно запрашивают семейства через кэш метаданных; успешное семейство за текущую дату не обходится заново. Резервный опрос — не чаще раза в минуту, только пока вкладка открыта. Лимит котировок отключает автоматический резервный опрос до конца сессии; ручной `R` остаётся доступен.
- `A`/`Ф` в таблице или профиле открывают заявку **только по действующему выбранному контракту MOEX**. Цена и торговый лот принадлежат этому контракту. Подмена тикера или отправка уже открытой заявки по серии, сменившейся при ролловере, отклоняется: откройте заявку заново. Без маски, счёта или известной экспирации торговля недоступна; международная котировка остаётся доступной.

## Настройка commodities.json

Файл `~/.finam-cli/commodities.json` создаётся при первом запуске рядом с токеном (Windows: `C:\Users\<Имя>\.finam-cli\commodities.json`). [Полный шаблон](../../config/example/commodities.json) содержит девять строк и только пользовательские настройки, без сохранённых контрактов и дат. Пример одной строки какао:

```json
{
  "enabled": true,
  "order": ["CC"],
  "commodities": {
    "CC": {
      "symbol": "CC@IFUS",
      "name": "Какао",
      "decimals": 2,
      "moex_mask": "CC*@RTSX",
      "roll_days": 5,
      "conversion": {
        "multiplier": 1000,
        "fx_symbol": "USD000UTSTOM@MISX",
        "fx_operation": "divide"
      }
    }
  }
}
```

- `enabled: false` полностью скрывает вкладку и выключает её запросы.
- Ключ (`CC`) — код строки; `symbol` — полный код котировки; `name` — описание; `decimals` — число знаков (0–8). `moex_mask` — маска по полному символу с `@RTSX`, например `NG*@RTSX`, `BR*@RTSX`, `SF*@RTSX`; пустая маска означает только просмотр. Маска начинается с буквенного/цифрового префикса семейства, а не с `*`.
- `order` задаёт порядок строк. Не перечисленные в нём товары добавляются в конце по алфавиту.
- Некорректный файл не перезаписывается: вкладка отключается, причина записывается в журнал.
- `expiry_warning_days` — число дней до экспирации для предупреждения; если поле отсутствует, используется 5. Значение неотрицательное и не заменяет `roll_days`, который управляет выбором серии.
- `roll_days` — неотрицательное число календарных дней. Выбирается самая ранняя экспирация **строго позже** текущего времени плюс этот запас; при достижении границы контракт заменяется следующим доступным. При `0` переключение происходит на самой экспирации. Месячные, квартальные и нерегулярные серии выбираются одинаково, без генерации кодов и догадок о датах.
- Сохранённые контракты находятся отдельно, в `~/.finam-cli/commodities_cache.json`. Это объект с ключами-масками (`NG*@RTSX`, `SF*@RTSX` и т. п.). Каждая запись содержит `updated_at`, `roll_days` и один `contract` с полями `symbol`, `name`, `expiration`, `decimals`; списки будущих серий не сохраняются. Кэш общий для всех счетов, без их идентификаторов. Обновление атомарно заменяет файл кэша, сохраняя остальные семейства; пользовательский `commodities.json` не изменяется. После перезапуска сохранённый неистёкший контракт доступен сразу, даже без выбранного счёта; счёт нужен для запросов брокеру и торговли.
- Отсутствующий или повреждённый кэш не отключает вкладку: контракт будет найден заново, а успешный поиск восстановит файл кэша. Кэш можно удалить, не затрагивая настройки. Старая секция `futures` в `commodities.json` больше не читается; её можно удалить. После перехода на отдельный кэш первый поиск выполняется заново.
- Успешный пустой ответ кэшируется только для той же локальной даты и того же `roll_days`. После изменения запаса дней и перезапуска поиск не блокируется прежним пустым ответом.
- Свежесть определяется **локальной календарной датой**. После полуночи ближайший пятисекундный фоновый тик обновляет метаданные только сохранённого активного контракта, даже на другой вкладке. Поиск серий выполняется при первом выборе или достижении границы `roll_days`, в том числе внутри текущей даты; затем сохраняется только выбранный следующий контракт. Без сети будущая серия не выдумывается: прежний контракт остаётся доступен до экспирации, после неё исключается из отображения, подписки и заявок. Ошибка сохраняет прежний контракт и дату успешного обновления; повторная попытка — в новую дату или по `R`. Лимит метаданных приостанавливает автоматические запросы до новой даты; ручной `R` доступен.
- Значение `conversion` **не меняется**: `multiplier` масштабирует цену MOEX (по умолчанию 1), затем применяется необязательная операция `divide`/`multiply` с курсом. Приведённая цена и дельта выводятся с точностью `decimals` международной серии; сама строка MOEX — с точностью контракта. Дельта вычисляется до округления.
- Какао: `481.3 RUB/кг × 1000 / 84.41 RUB/USD ≈ 5701.93 USD/т`; при Commodity `5609 USD/т` дельта ≈ `+92.93 USD/т`. Это пересчёт по рыночному курсу, **не официальная цена исполнения**: в [правилах MOEX](https://www.moex.com/s3513) применяется курс ЦБ. Кофе: `2.908 USD/фунт × 100 = 290.8 ¢/фунт`.
- ES связан с `SF*@RTSX`, фьючерсом на [SPY ETF](https://iss.moex.com/iss/securities/SFZ6.json?iss.meta=off). Масштаб `×10` приводит цену MOEX к масштабу международной серии: `776.8 × 10 = 7768`, при Commodity `7748` дельта `+20`. Это приближённый прокси, а не точный эквивалент ES. Разные сроки, время сделок, валютный базис и свойства ETF могут входить в дельту; сама по себе она не доказывает арбитраж.
- Старое `moex_symbol` нужно удалить и заменить на `moex_mask` и `roll_days`; иначе конфигурация отклоняется с понятной записью в журнале. После изменения файла перезапустите программу.
